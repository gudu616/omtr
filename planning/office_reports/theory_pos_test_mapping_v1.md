## §1 裁定：資料源＝`clean.per_tok`，不是 corrupted，不是 patched

**裁定**：Δ 一律算在 `records[<item>]["clean"]["per_tok"]` 上。
不使用 `corrupted.per_tok`，不使用 `patches[*].patched.per_tok`，不使用 `rank_per_tok`。

**理由**：§7.7 第 659–662 行講的是「per-token gold 應該在被高 count 窗覆蓋的位置上明顯較高」
與「升高應該平均分布在整段」——問的是**基線的 gold 可預測度怎麼沿著段落分布**，
是介入之前就存在的量。patched 讀數已經被 corruption 選點與 band 選擇這兩層裁決汙染，
拿它算 Δ 等於讓 §7.7 的結論依賴 §7.7 以外的裁決。

**這條是為了什麼**：讓「劑量這個詞有沒有位置解析度」這件事，跟因果介入完全脫鉤。
§7.7 是唯一能分開 (i) 與 (ii) 的檢定（§7.4 已經證明語料交叉那條路在現有規模下是死區，
需要約 290 題）——它必須乾淨到不管因果階段解盲成什麼樣都還站得住。

**永遠達不到的情形**：`clean.per_tok` 缺失，或長度不等於 `n_gold_tokens`。
**已量：5 個分片、所有 L0 題，`len(clean.per_tok) == n_gold_tokens` 成立，0 例外，
無任何缺 `clean` 的題。** 這條目前咬 0 題。

## §2 裁定：題集＝L0 union 讀法，含 rank-guard ERR 題，不含 L0P/L0N/L0M

**裁定**（**五**個條件同時成立才進檢定；第 5 條為 v1.1 新增）：

1. `id` 以 `L0-` 開頭（**只有 L0**）；
2. 該題出現在該模型的 `results/causal/main_winB1_patch_<model>.json` 的 `records` 裡，
   且 `clean.per_tok` 存在、長度 == `n_gold_tokens`；
3. 該題的 `battery.json` `title` 能在 `battery/l0_verification.json` 找到同名條目
   （**join key ＝ `title`，不是 id**——`l0_verification.json` 沒有 id 欄位）；
4. 該題在 §3 的門檻下窗內與窗外都非空；

   （Pythia→`pile`、OLMo→`olmo_mix`；等價寫法＝`CORPUS[model] in battery_item["verified_in"]`）。

## §3 裁定：「高 count 窗」＝逐題自己的 10 個 gold 側窗、q=0.75 分位、count ≥ 門檻

**裁定**：

- **前置條件**：先過 §3-0 的語料閘。**沒過閘的 (題, 模型) cell 不產生窗標籤。**
- **窗的母體**＝該題 `l0_verification.json` 條目裡，**完全落在 gold 區間內**的 probe。
  **已量：每題恰好 10 個**（見 §4 與 §8）。
- **語料的選擇**：Pythia 四模型用 `probes.pile`；OLMo-2-1B 用 `probes.olmo_mix`。
  **每個模型只用自己訓練語料的 count。**
- **只用 `status == "ok"` 的 probe。**（**已量：440/440 全部 `ok`，`n_unknown` 全 0。
  這條規則目前咬 0 個 probe**，仍寫進來是為了擴題時有現成規則。）
- **門檻**＝該題自己那 10 個 count 的 **0.75 分位**（`numpy.quantile(c, 0.75)`，
  預設 `linear` 內插）。**高窗 ⟺ `count >= 門檻`**。
- **逐題定門檻，不用跨題全域門檻。**

**理由**：

- **q=0.75 不是為這個檢定新發明的門檻**——它是本專案既凍的分位制參數
  （`.agents/dept_memory/shared.md` 凍結值速查：「分位制 q=0.75、存活≥12、適足≥10×底線」）。
  理論部自訂規矩第二條是「報界線不發明門檻」，所以這裡引既凍值，不新設。
- **逐題而非全域**：count 的量級跨題差**約兩個數量級**。
  全域門檻會讓低量級的題整題落在門檻下（窗內為空、退出），高量級的題整題在門檻上
  （窗外為空、退出）——那不是分不開，那是把題篩掉。

  > **⚠ 可見更正（v1.1，審查部修 7）**：v1.0 寫「差**三個**數量級（L0-18 是 77，L0-11 是 5719）」，
  > 兩處都錯。(a) 77→5719 是 **74×＝1.87 個**數量級，不是三個；
  > (b) **逐題 pile 最大值其實是 L0-06＝6042**，不是 L0-11 的 5719；
  > (c) 更糟的是 **L0-18 根本不該被拿來當 pile 側的例子**——它沒過 Pile 閘（§3-0），
  > 四個 Pythia 分片都沒有它，它的 pile count 不進任何一條算式。
  > **正確的數字（已量，過閘題的 gold 側窗）**：逐題最大值最低是 **L0-15＝90**、
  > 最高是 **L0-06＝6042**，比值 **67×＝1.83 個數量級**；單一 probe count 全距 **0 到 6042**。
  > **裁定不變**——1.8 個數量級一樣足以讓全域門檻把題篩掉。
- **各用各的語料**：§7.4 已量到兩個語料的 count 本身相關 0.926，但 OLMo 的
  「自己−另一個」是 +0.157 而四個 Pythia 全負。拿 Pile count 當 OLMo 的曝光代理
  是**錯的代理**，不是保守的代理。

**這條是為了什麼**：讓「窗內 / 窗外」這個切法在看資料前就是一個確定的、
可由字串與 count 重算出來的**遮罩**，不是一個看了 per_tok 才調得剛好的旋鈕。

**永遠達不到的情形**：
q 往 1.0 走 → k→1，窗內只剩一個 7 詞窗（約 10 個 token），逐題 Δ 噪音爆掉；
q 往 0 走 → k→10，窗外為空、Δ 無定義。
**已量：q=0.75 下，17 題 × 兩個語料，高窗數 k 一律等於 3**（分布 `{3: 17}`，兩個語料皆同）。
**窗內約占 40%、窗外約 60%（字元中位數約 94／144）**，**0 題退化**。這條在 q=0.75 上是穩的。
（v1.1 更正：v1.0 此處寫「字元數約 40/60」，那是百分比不是字元數——審查部修 6。）

**必附的敏感度分析（預先登記，不改判定）**：q=0.60 與 q=0.90 各跑一次，
與 q=0.75 並列報。**判定一律以 q=0.75 為準**，另外兩個只揭露穩健性。

### D. 窗 → token 集合

gold token `j` 屬於窗 `[s, e)` ⟺ `offsets[n_prompt+j-1]` 與 `[s, e)` **有非空交集**
（任何字元重疊即算，不要求整個 token 被包住）。

- `in_mask(題) = ∪ over 所有高窗`（重疊處**以「屬於窗內」為準**）；
- `out = gold token 全集 − in_mask`。

**重疊以窗內為準的方向（v1.1 更正為雙向陳述）**：窗會互相重疊，一個 token 可能同時被高窗與低窗蓋到。
判它窗內，會把一些「其實比較像窗外」的 token 拉進窗內，**稀釋對比、把 |Δ| 往 0 推**。

- **對 (i)：保守**（逆風，讓「窗內明顯較高」更難成立）。
- **對 (ii)：反保守**——把 |Δ| 推向 0 會讓 §7 的等價檢定（90% CI 落在 ±0.2 內）**更容易通過**。

> **⚠ 可見更正（v1.1，審查部修 9）**：v1.0 這裡無條件寫「**是保守的**」，然後只論證了 (i)。
> **§7.7 是三分決策，沒有單一的保守方向**；任何「這個處理比較保守」的宣稱，
> 若沒指明是對 (i) 還是對 (ii) 保守，就是無定義。
> 諷刺的是我自己在 §7 警覺過同型風險（「(ii) 會靠一個過窄的區間『通過』，那不是證據，是算法」），
> **卻沒把同一個警覺套到點估計上。**
> **裁定不變**（仍採「有字元交集即算窗內」），但**等價那一支的結論必須併同本規則的稀釋效應一起揭露**。

### E. 跨界窗的處置（工單指名要凍的那一條）

**裁定：每題第 11 個 probe（8 詞、跨 prompt/gold 交界的那一個）一律排除，且逐題記入揭露。**

**理由**：它的 count 同時由 prompt 側與 gold 側的字串貢獻，而 prompt 側**沒有 per_tok**。
把它算進來，就是「劑量施加的支撐集與結果量測的支撐集不同」——
跟 §7.5 第 3 點打掉 v0.7 劑量單位的**同一個病**。既然那個病在語料側被認了，
就不能在 token 側再犯一次。

**排除的規模（已量）**：每題恰好 1 個，20/20 題皆如此，
排除後每題剩 10 個窗——這也是 §3「窗的母體恰好 10 個」的來源。

**永遠達不到的情形**：若某題排除跨界窗後剩下的 gold 側窗少於 2 個，
分位門檻沒有意義，該題退出。**已量：不會發生，每題都是 10 個。**

## §5 裁定：「≥4/5 run」的對應——主裁決＝四個 fp32 run，門檻升為 4/4

這是本裁定書最有爭議、也最需要覆核的一條。工單問了兩題，兩題都裁。

### 5-a　五個模型算不算五個 run？——**主裁決算四個，2.8b 退出**

**裁定**：主裁決的 run 集合 ＝ 五個分片**扣掉 `causal_analysis.DESCRIPTIVE_MODELS`
（`causal_analysis.py:52`，v2.19）**，即 `pythia-410m`、`pythia-1b`、`pythia-1.4b`、
`OLMo-2-0425-1B` 四個，全部 fp32。**`pythia-2.8b` 退出主裁決，照 v2.19 出描述性數字，兩邊都報。**
**清單以那個凍結常數為唯一出處，位置檢定不得另抄一份**（理由見 §5-c）。

**「≥4/5」的重新對應：≥4/4**（比例讀法 ≥0.8；3/4 = 0.75 不及格）。

**理由**：

1. **v2.19 是既凍規則，字面就是「2.8b 降為描述性，退出主裁決」。** §7.7 是主裁決
   （它決定「劑量」這個詞存不存活、v0.7 的外部錨保不保得住「模型外部」身分）。
   為它另開一個「§7.7 不用 DiD 所以不受降級管」的範圍例外，就是**護欄咬人之後放寬**——
   而 v2.19 自己寫著「護欄咬人後不放寬，雙向適用」。
2. **我確實想得出一個放行的物理論證**（per_tok 的位置對比是同一次 forward 內部的差，
   fp16 的解析度遠細於 ~0.1 nats 級的對比），**但我沒有量過它**。
   理論部自訂規矩第一條：**推的不得承載判定。** 所以不放行。
3. **方向保守，兩支皆然**：
   - 對 **(i) 支持門檻**：4/4 比 4/5 嚴——任何一個 run 落空就結束。
   - 對 **(ii) 等價門檻**：run 少一個，聯集題集**不變**（2.8b 的 12 題是其他四個聯集的子集，
     見 §2），但每題的 cell 數從 4 降到 3～4，**bootstrap 的 CI 變寬 → 更難落進 ±0.2**。

**必附的非獨立性揭露**：四個 run 裡有**三個是 Pythia**，共用同一個 tokenizer、
同一個訓練語料（Pile）、**同一組窗標籤**，訓練資料互相嵌套。它們是三個高度相關的 run，
不是三個獨立證據。**「4/4」的實質獨立單位大約是 2 個（Pythia 家族 1 ＋ OLMo 1），不是 4 個。**
這句必須進論文，不能只留在這裡。

### 5-b　OLMo 算不算 run？——**算，但只能配 olmo_mix 的 count**

**裁定**：OLMo-2-0425-1B **算一個 run**，其窗標籤一律取自 `probes.olmo_mix`。
**嚴禁**拿 Pile count 當 OLMo 的曝光代理。

**理由**：§7.7 檢定的是「曝光落在哪些位置」。曝光的定義依賴模型看過什麼語料。
OLMo 沒看過 Pile，Pile count 對它不是保守的代理，是**錯的**代理。
用錯的代理算出來的 Δ 不管正負都不能承載判定。

**這條對兩個判準的影響**：

- 對 **(i)**：OLMo 是四個 run 裡唯一的非 Pythia、非 Pile 單位。
  **它同時是這個檢定唯一的外部效度，也是 §0-1 那個「永遠達不到」的最可能觸發點。**
  §7.4 已量到它在語料歸屬上與 Pythia 方向相反（+0.157 vs 全負）。
  **把它踢掉會讓 (i) 好過很多——正因為如此，不准踢。**
- 對 **(ii)**：OLMo 的 count 量級遠高於 Pile（例：L0-11 olmo_mix 最大 120128 vs pile 5719），
  但門檻是**逐題分位**，所以量級差被吸收掉，選出的高窗數一樣是 k=3。
  影響只透過「選到哪三個窗」進來——**已量：兩個語料選出的高窗不完全相同**
  （例 L0-02：pile 窗內 125 字元、olmo_mix 窗內 80 字元）。這是真實的、預期中的差異。

### 5-c　⚠️ 儀器 bug：不得用 `backend_dtype` 欄位篩 run

## §6 裁定：Δ 的計算與置換檢定配方

### 6-a　逐題 Δ

```
Δ(題 i, run r) = mean( clean.per_tok[j]  for j in in_mask(i) )
               − mean( clean.per_tok[j]  for j in out(i) )
```

單位 **nats**。per_tok 是 log 機率（負值），所以 **Δ > 0 ⟺ 窗內 token 被預測得比較好**，
方向與 §7.7 第 659–660 行的 (i) 預測一致。

**逐題等權**：窗內、窗外各自取**未加權平均**，長題不因為 token 多就佔便宜。

### 6-b　聚合與家族統計量

**逐 run 統計量 ＝ 該 run 各題 Δ 的 studentized 平均**，跨 run 用聯集＋遮罩讀法。
**出處**：`causal_analysis.py` 第 9 行凍結出處塊「家族統計量＝各 run studentized 均值」，
附錄 D3/E2（v2.13 G 案）。**不新發明統計量。**

### 6-c　置換單位——**窗標籤，不是 token，不是題**

**裁定**：置換單位＝**逐題把 10 個 count 值重新隨機指派到 10 個窗位**，
重算門檻與遮罩，重算該題 Δ。

> **v1.1 對「為什麼選它」的重新表述**：選它的理由是**它條件在真實的窗幾何上、
> 不假設 Δ 對稱於 0、虛無支撐集受 C(10,3)=120 的設計限制**——三條都是結構性優點，
> 且審查部盲推也獨立選了同一個。
> **不是**因為它比 sign-flip 更嚴（實測不成立，見下方更正塊與 §10-2）。
> **它本身不足以把位置混淆關住**，所以 §6-e 另設閘門。

**明確排除的兩個替代方案與理由**：

- **逐 token 打散標籤 → 不採。** per_tok 有強烈的序列自相關（起手窗特別難、
  段落後段變容易），打散 token 標籤會摧毀這個結構，讓虛無分布過窄、p 值過寬鬆。
- **逐題翻轉 Δ 的正負號（即凍結的 `family_permutation` sign-flip）→ 不採為主裁決。**
  理由是 §0-5 量到的位置混淆：高 count 窗系統性地稍微偏早（平均相對位置 0.361 vs 0.431），
  且**含起手 token 的第一個窗在 9/17 題是高窗**。sign-flip 的虛無分布**不包含**
  「這些位置本來就比較難／比較容易」這個效應，所以它分不開
  「count 預測了升高」與「高 count 窗剛好坐在容易的位置上」。
  ~~**窗標籤置換把位置幾何固定住、只讓 count 標籤動，那個純位置效應就被關進虛無分布裡。**~~

> **⚠ 可見更正（v1.1，審查部修 3 — 本次最重要的一條）：刪除線那句撤回。**
>
> **撤回的理由在定稿時換過一次，兩個版本都留著：**
> **初稿的理由**＝「實測起手窗混淆下 FPR 膨脹到 .1 以上」；
> **定稿的理由**＝「那個膨脹是窗層級顆粒度造成的高估（見下方定位塊），
> 但**這句話本來就不該講**——窗標籤置換確實吸收平滑位置變化、確實不吸收集中在單一窗位的效應，
> **它從來沒有把位置效應『關進虛無分布裡』，只是在某些顆粒度下那個效應剛好小到無所謂**。」
> **撤回維持，理由更保守。**
>
> 審查部用合成資料量了，我**獨立重寫一支再量一次**（兩邊都用真實窗幾何＋真實 pile count，
> 合成的 gold 值只受位置影響、**count 效應嚴格為 0**，所以理想偽陽性率就是 .05）。
>
> **兩件事分開講：**
>
> **(甲) 平滑的位置梯度——確實被吸收，這半句站得住。**
>
> | 位置梯度 β | 審查部量到的 FPR | 我重跑 |
> |---|---|---|
> | 0.0 | .055 | .059 |
> | 0.5–1.0 | .050／.055 | .070／.069 |
> | 2.0 | .022 | .029 |
>

> 而實測偏移只有 0.431−0.361 = **0.069，約 0.35 個 SD**——**本來就被隨機標籤的自然波動蓋過去。**
>
> **(乙) 起手窗那種集中在單一窗位的效應——⚠ 這一段的兩組數字後來雙雙降格，見下方定位塊。**
>
> **以下是 v1.1 初稿當時的兩組數字，原樣保留供對照，但都已不作為判定依據：**
>
> | 起手懲罰 A | 審查部量到的 FPR（其後自撤） | 我重跑（其後查明為窗層級高估） |
> |---|---|---|
> | 0.0 | .045 | .049 |
> | 0.5 | （未測） | .160 |

>
> | 起手懲罰 A | 不補救 | **R1 剔掉前 ~2 個 token（＝§6-e-2）** | **R2 剔掉整個第一窗** |

> 卻不對稱地改了正規化，反而放大偏誤。**R2 在整個範圍內把 FPR 釘回 .06。**
>
> **這不是我自創第三案**：審查部自己的 §1(g) 寫的就是「把第一窗（含起手 token）**整個拿掉**
> 再跑一次」，是它 §4 修 3 的修法在指回 §6-e-2 時把兩件事混成一件
> （並誤寫「零件都在，只有地位寫錯」）。**本裁定採 R2，已回報統籌代理並記錄理由。**

**跨 run 共用抽樣（強制）**：每個 replicate、每一題**只抽一次**窗標籤重排，
**套用到所有 run**。這是為了保住 run 之間真實存在的相關（三個 Pythia 共用窗標籤）。
若逐 run 獨立抽，虛無變異被低估，p 值過寬鬆。
**這個作法有凍結先例**：`causal_analysis.py` 第 180 行的 `fam.S` 形狀是 `(B_PERM, mm)`——
**一題一個符號，跨 run 共用**，本裁定只是把同一個性質搬到窗標籤上。

## §7 裁定：等價判準 ±0.2 nats 的 CI 算法

**裁定**：

- **被檢定的量**＝**聯集的逐 cell Δ 池化平均**（把所有 (題, run) 的 Δ 串起來取平均）。
  出處：凍結的 `family_permutation` 回傳的 `mean_diff_nats` 就是這樣算的
  （`causal_analysis.py:186-187`：`pooled = np.concatenate([...])`），
  `tost_family` 亦同（第 196–199 行）。**不另立加權方式。**
  副作用要揭露：題數多的 run 權重較大（410m 有 16 題、2.8b 12 題）。
- **CI 方法＝非參數 percentile bootstrap，重抽單位＝「題」（cluster bootstrap）。**
  抽到一題就把**該題在所有 run 上的 cell 整包帶走**。
- **90% CI ＝ 第 5 與第 95 百分位。**
- **B = 20000、seed = 20260822**（同 §6-d，單一出處）。
- **通過條件：CI 的兩個端點都嚴格落在 (−0.2, +0.2) 之內。**

**理由**：

- **bootstrap ＋ 90% 是本專案的既有方法，不是我新選的**：§7.4（`theory_v3_final.md`
  第 589–590 行）報的就是「自助法 90% CI：pythia-1.4b [−0.310, +0.030]、
  OLMo [+0.044, +0.306]」。
- **為什麼抽「題」而不抽 cell**：三個 Pythia 在同一題上的 Δ 是近乎重複的觀測
  （共用窗標籤、共用語料、訓練資料嵌套）。獨立抽 cell 等於把 3～4 個相關觀測
  當成 3～4 個獨立觀測，**CI 會偏窄 → 等價變得太好過**。
  cluster bootstrap 是這裡唯一保守的抽法。
- **為什麼不用 t 分布**：逐題 Δ 是兩個平均的差、樣本數 n=17、
  分布形狀未知且很可能重尾（單一 token 的 log-prob 可以很極端）。

### 7-a　【v1.1 新增‧應修】逐題 run 數表：cluster 大小很不平均，兩題是單證人

統籌代理指出（審查部順手量到）**單證人題要點名**。我自己重跑了逐題歸屬：

| 逐題進入的 fp32 run 數 | 題數 | 是哪些題 |
|---|---|---|
| **4／4（全員）** | 13 | L0-01～07、11、15、16、17、19、20 |
| 3／4 | 1 | L0-08（缺 1b） |
| 2／4 | 1 | L0-09（只有 410m、1b） |
| **1／4（單證人）** | **2** | **L0-10（只有 410m）、L0-18（只有 OLMo）** |

**fp32 主臂總 cell 數 ＝ 59**（不是 17×4=68——**這個差就是 dof 灌水最容易發生的地方**）。

**這張表為什麼要在這裡（三個後果）**：

1. **cluster bootstrap 的 cluster 大小是 1～4，不是固定 4。** L0-10 與 L0-18 各自是
   **只有一個 cell 的 cluster**；抽到它們時，那一次重抽對池化平均的貢獻完全由單一模型決定。
   這不使方法失效（cluster bootstrap 本來就允許不等大小），但**它是 CI 寬度的真實來源之一，
   不能在報告裡被講成「17 個等價的題」**。
2. **「4/4 run 為正」是逐 run 聚合後才評估的**，不是逐題要求四個 run 都為正。
   4 個題（L0-08/09/10/18）本來就不可能在全部四個 run 出現——
   union＋遮罩讀法（`causal_analysis.py:166–175`）就是為這件事設計的。
3. **單證人題的方向不可單獨解讀。** L0-10 若在 410m 上呈現極端 Δ，那既可能是題的性質、
   也可能是該模型的性質，**這批資料裡沒有第二個證人能把兩者分開**。
   照本專案慣例：**點名，但不從它們身上讀出結論。**

**指令**：見 §9 附錄第 9 條。
  常態近似的 t 區間在 n=17 且重尾時會低估寬度。

**這條是為了什麼**：等價檢定是唯一能讓 (ii) 拿到正面結論的路。
如果 CI 算法選得太寬鬆，(ii) 會靠一個過窄的區間「通過」，
而 v0.7 的外部錨會**因為一個統計選擇**而失去「模型外部」的身分——
那不是證據，是算法。

**永遠達不到的情形（已算，這是 §0-2）**：

以常態近似寫出可行界。半寬 `h ≈ 1.645 × SD(Δ_題) / √n`，通過需要 `|Δ̂| + h ≤ 0.2`。

| n（題） | Δ̂ = 0 時，SD(Δ_題) 的上限 |
|---|---|
| 17（聯集） | **0.501 nats** |
| 12（交集，備查） | **0.421 nats** |

**若 Δ̂ 不等於 0，預算還要再扣**：例如 Δ̂ = 0.10 時，n=17 需要 SD ≤ 0.251 nats。

**我的先驗（明文不承載判定）**：逐題 Δ 的 SD 很可能大於 0.5 nats，
所以 **(ii) 大概率永遠達不到，本檢定的實際輸出大概率是「(i) 過或不過」＋「(ii) 無定論」**。

**這條先驗對應的「永遠達不到」句（鐵律要求，明文寫死）**：
**只要逐題 Δ 的標準差超過 0.501 nats（n=17），(ii) 就沒有任何觀測結果能通過——
包括真實效應恰好等於 0 的世界。** 換句話說，**(ii) 沒過這件事，
在 SD > 0.501 的情況下不帶任何關於 (i) 或 (ii) 誰為真的資訊，它只說明這台機器的題數不夠。**
判定書要求：報告時**必須先報 SD 與 CI 半寬，再報等價通過與否**；
若 SD > 0.501，等價那一支一律寫成「**檢定不可執行**」，不得寫成「等價未通過」。

**現在先講，是為了結果出來時沒有人可以說「等價沒過所以支持 (i)」**——
等價沒過只代表**沒問到**，不代表 (i) 成立。這兩件事在報告裡必須分開寫。

## §8 兩處推翻工單前提的更正（＋一個既有 bug）

工單寫「v0.7.1 更正案已知名言在 prompt 側未被量——這類窗要明文排除並記入揭露」。
**我做了純字串覆蓋稽核，這個前提在 probe 層級不成立。**

**稽核方法**（不碰任何 per_tok）：20 個 L0 題 × 11 個 probe × 2 個語料，
用 `causal_patch.item_prompt_gold` 的接法重建 `full = prompt + " " + gold.strip()`，
對每個 probe 做 `full.find()`，依落點分成 prompt-only / gold-only / 跨界 / 找不到。

**結果**：

| 類別 | 數量（20 題 × 11 probe） |
|---|---|
| 完全落在 gold 內 | **200**（每題 probe 0–9） |
| 完全落在 prompt 內 | **0** |
| 跨 prompt/gold 交界 | **20**（每題第 11 個，8 詞那個） |
| 找不到 | **0** |
| 同一 probe 在 full 裡出現多於一次 | **0** |

**所以**：

1. **「排除 prompt 側窗」這條規則實際咬 0 個 probe**；真正要排除的是**跨界窗**，
   每題 1 個，處置已凍在 §4-E。
2. **v0.7.1 更正案講的事情仍然成立，但它是文本層級不是 probe 層級**：
   名言（例如 L0-01 的「It is a truth universally acknowledged…」）確實在 prompt 裡，
   確實沒有被量——但它沒有被量是因為**沒有 probe 放在那裡**，
   不是因為有 probe 放在那裡卻落在 prompt 側。
   **這個區別要寫進論文**：per_tok 覆蓋的是 gold 續寫，
   **整題最高曝光的那一段（開頭名言）在結構上就不在檢定範圍內**。

   這是本檢定的一個**構念邊界**，也是它唯一無法回答的問題。
3. **我自己踩過的坑記在 §4-A**：漏掉那個前置空白，會讓 20 題全部誤判成「probe 找不到」。
