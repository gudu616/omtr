# 17. 操縱檢查（Manipulation Check）

**一句話白話版**：操縱檢查就是「先驗一下你想製造的那個條件真的有製造出來」——如果你想讓 L1 的題目「有唯一正解」、讓 L4 的題目「真的逼模型把兩個不相干的東西揉在一起」，動手量內部訊號之前，得先確認這兩個前提真的成立，不然量到的差異可能只是「操縱根本沒生效」的噪音，跟回憶或創造一點關係都沒有。

**為什麼本研究用得到**：如果 L1（回答常識）的模型其實常常答錯或答非所問，那量到的熵、收斂深度就不是「回憶的訊號」，可能只是「亂猜的訊號」；如果 L4（強迫混搭）的模型其實只顧了一邊題材、完全沒把兩個領域接起來，量到的訊號可能是「破功模式」而不是我們想研究的「混搭創造模式」。操縱檢查先把這兩件事釘住，才能放心說「條件之間的內部訊號差異，來自回憶 vs. 創造的假說,而不是操縱本身沒起作用」。

**再深一點**：我們目前用的操縱檢查是最陽春的字串比對——便宜、可自動化、不用另外叫一個 AI 來判斷，但代價是它只認得「一模一樣的字」，認不得「意思一樣但換句話說」。第一批 100 題的結果顯示兩個條件命運不同：L1 通過率 0.875（87.5%）——大多數時候模型真的把標準答案的關鍵字講出來了，操縱基本成立；但 L4 的雙域命中率量出來是整數 0——字面上看像「操縱完全失敗」，但打開實際輸出一看，其中一題（要求把「當地降雨量」跟「銀行存款利率」綁在一起的題目）模型確實把 rainfall（降雨）綁上了 interest rate（利率）——語意上碰到了混搭，只是它沒有寫出題目關鍵字本身的字面寫法（"weather"、"banking" 這兩個詞），陽春的字串比對因此判它「沒過」；但輸出隨即退化成同一句話的複讀迴圈，所以它同時是「字串檢查器誤判」和「1.4B 級模型行為端失敗」兩件事的例子：字面檢查抓錯了原因，語意品質也並不合格。這說明操縱檢查這把尺自己也可能有誤差，量出來的數字要配合實際輸出複查，不能盲目全信。

**在我們的程式碼／數據裡**：`harness/run_pilot.py` 的 `manipulation_check(item, greedy_text, samples)` 函式（第 150–162 行）。L1 分支在第 154 行做 `item["expected"].lower() in t.lower()`——標準答案的字串是否原封不動出現在輸出裡；L4 分支在第 156–159 行做 `a.lower().split()[0] in t.lower()`——題目兩個領域各自的第一個詞是否都出現在輸出裡。彙總邏輯在 `harness/analyze_pilot.py` 第 104–110 行，寫進 `results/analysis_EleutherAI_pythia-1.4b.json` 的 `l1_pass_rate`（0.875）與 `l4_both_domains_rate`（0.0）。誤判案例可在 `results/raw/pilot_EleutherAI_pythia-1.4b.json` 找到 `id: "L4-weather-1"`：它的 `manipulation.l4_both_domains` 是 `false`，但 `greedy_continuation` 明明寫著「...the interest rate is set by the total of the previous year's rainfall...」——`docs/PROCESS_LOG.md` 第十二步稱這是「粗糙的字串檢查器把少數真混搭也判了死刑」，記錄在案。後續已經換 AI 評審重新評分（見 `results/judge_scores.json`）：L4-weather-1 這題被判定為真的達成雙域綁定（pass，0–3 分制拿 2 分）——證實了字串檢查器當初的誤判。

**常見誤解**：
1. 「操縱檢查沒過 = 那個條件的所有數據都不能用」——不對。字面沒過不代表語意沒過；正確做法是先分層看待，人工或用 AI 複查極端值（尤其是像 L4 這種全滅、看起來可疑的訊號），而不是整批直接丟棄。
2. 「操縱檢查只是統計上的形式手續，做不做都行」——不對。沒有它，你完全無法區分「模型內部訊號的差異來自回憶 vs. 創造的假說」還是「差異只是因為操縱根本沒生效、你量到的其實是別的東西」；它是後面所有因果性主張的前提，不是錦上添花。

**答辯模擬題**：
- Q：L4 的雙域命中率是 0，那 L4 條件下量到的熵、收斂深度數據還可信嗎？
  A：字面上的 0 確實是警訊，而且已經證實至少一個假陽性；換成 AI 評審語意重新評分後（見 `results/judge_scores.json`），Pythia-1.4B 的 12 題 L4 裡語意上真正達成雙域綁定的也只有 1 題（就是被字串檢查器誤判的 L4-weather-1）——字串檢查器的 0 低估了一點點，但語意版的真實通過率依然很低（約 1/12），L4 的結論仍然只能標記為初步、不拿它做強主張，`docs/PROCESS_LOG.md` 裡也誠實記錄了這個限制。
- Q：為什麼不一開始就用更聰明的方法做操縱檢查，比如叫另一個 AI 判斷語意？
  A：pilot 階段先求便宜、可重現、零額外 API 成本的陽春版本，用它先篩出訊號的大致方向、也順便暴露出操縱本身可能有問題的地方；等要下比較有把握的結論時，再升級成 AI 評審做語意判斷——這也是操縱檢查本身要被驗證、不能無限信任自己量尺的例子，跟卡 11 講的對照組邏輯是同一種紀律。
