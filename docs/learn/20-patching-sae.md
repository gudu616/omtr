# 20. 下一步的工具預告（Activation Patching ＋ SAE）

**一句話白話版**：我們現在手上的所有數據（熵、收斂深度、效應量、劑量反應）都只能回答「回憶和創造時，模型內部長得不一樣」，答不了「這個不一樣的地方，是不是真的造成了行為的不同」。**Activation patching**（活化值置換）是「移植手術」：把一次跑（比如創造模式）某一層的內部訊號，強行換成另一次跑（回憶模式）的訊號，看輸出會不會跟著變成回憶模式的樣子。**SAE**（稀疏自編碼器，sparse autoencoder）則是「把一團混在一起的訊號，拆成一排排各自有意義的獨立旋鈕」，讓你不只知道「哪一層不一樣」，還能知道「哪一個具體的概念在起作用」。

**為什麼本研究用得到**：我們現在的證據性質全部是相關（correlational）——例如卡 16 的劑量反應只能說「記憶強度和收斂深度一起變動」，沒辦法排除「兩者其實都是被第三個東西一起驅動，比如題目本身有多罕見」這種可能。要證明「內部某個特定成分真的是造成回憶／創造差異的原因」，就得做因果實驗：主動去干預那個成分，看行為是否照著預測的方向改變——這正是 activation patching 要做的事。而 SAE 要解決的是另一個問題：目前我們的「訊號」是整條殘差流的高維向量，看得出「不一樣」但說不清楚「哪個概念不一樣」；SAE 把這條向量拆成一排排大多數時候是 0、只有少數被點亮的「特徵」，每個特徵通常對應一個相對可解讀的概念，方便我們檢查回憶模式和創造模式各自點亮了哪些旋鈕。

**再深一點**：activation patching 的具體做法是——先讓模型分別跑一次「回憶」輸入和一次「創造」輸入，把兩次跑的過程中、某一層某個位置的殘差流向量（見卡 04）都記下來；然後重新跑「創造」輸入一次，但在那一層那個位置，把本來該有的創造向量換成剛剛記下來的回憶向量，繼續往下算，看最後輸出的機率分布會不會被拉向回憶模式的樣子。如果換了之後輸出真的變了，代表那一層那個位置的訊號對行為有因果性的貢獻，不只是伴隨發生的相關訊號。SAE 則是另外訓練一個小型的自編碼器，逼它用「大多數維度是 0、只有少數被啟動」的方式去重建原本的殘差流向量——這個稀疏限制會逼著它把混疊在一起的多個概念拆開，讓每個維度盡量只代表一件事。本研究計畫用 Neuronpedia 這個 API 讀現成的 Gemma Scope（已經幫 Gemma 系列模型訓練好的公開 SAE 特徵庫），繞開自己從頭訓練 SAE 的算力門檻；本機版的 Gemma-2-2B 因為是 gated model，需要使用者的 HuggingFace token 授權，目前列為後續階段。

**在我們的程式碼／數據裡**：這兩項工具目前都還沒寫進 `harness/`。技術路線規劃列出「機制工具：TransformerLens（Pythia）＋ nnsight（OLMo-2 後備）；logit-lens、熵剖面、RSA、activation patching」與「SAE 特徵：後期用 Neuronpedia 免費 API 讀 Gemma Scope；本機 Gemma-2-2B 需要使用者 HF token（gated）→ 待授權」，把它們定位成尚未動工的下一步；階段規劃把它們排在發表後的因果階段（待授權：Gemma Scope 特徵層——Neuronpedia API 或本機 gated Gemma；熟悉度方向 steering），狀態是「被授權阻塞」。這卡在事先定下的停止條件第 3 條——「需要花錢…或帳號授權（HF token 接受 Gemma license、Neuronpedia API key）」——本機路線要 Gemma 的 gated token，Neuronpedia API 路線也要申請 API key，兩條路都需要使用者親自去按下這個授權開關，不是技術上做不到。

**常見誤解**：
1. 「反正組內相關都到 −0.86、p<0.0001 這麼顯著了，因果應該也差不多確定了吧」——不對，統計顯著再加上中等的效應量，也可能是第三變量（例如題目本身有多罕見）同時驅動了記憶強度和收斂深度這兩個變量；activation patching 是唯一能把「這個成分是不是原因」直接證明或推翻的方法，統計顯著性不能替代它。
2. 「SAE 只是換個方式畫圖，沒有 logit lens（卡 06）或熵（卡 07）那麼重要」——不對，logit lens／熵是看「整條殘差流」這個黑箱的宏觀讀數，SAE 是打開黑箱把它拆成一個個可以分別檢查的零件；兩者回答的問題不在同一個層次，SAE 是為了在「找到有訊號的層」之後，進一步問「這個訊號裡具體是什麼概念在作用」。

**答辯模擬題**：
- Q：你現在的資料已經有顯著的效應量和劑量反應了，為什麼還說「還不到突破」，一定要做 patching 不可？
  A：因為目前全部的證據都只是相關——回憶題和創造題本來就在很多面向不同（字面重複度、句子稀有度），我們沒辦法單靠相關數據排除「其實是別的原因造成內部訊號不同，不是回憶 vs 創造本身」；activation patching 主動干預、直接看行為會不會照著預測的方向改變，才是回答「這是不是因」的實驗，不是觀察。
- Q：為什麼不現在就做 SAE，非要等 Gemma 的使用者授權？
  A：因為我們現在的主力模型是 Pythia 和 OLMo-2（教材公開才能用 infini-gram 查證記憶）；Pythia 系列雖有公開 SAE（多為 70m/160m 等小尺寸），但沒有對應我們這兩個 checkpoint（pythia-1.4b、OLMo-2-0425-1B）的現成特徵庫，Gemma Scope 才是目前最完整的免費 SAE 資源，但綁在 Gemma 系列上——不管走 Neuronpedia API 讀現成的，還是在本機自己跑 Gemma 模型，都需要使用者去處理一個帳號授權的門檻，這正是停止條件第 3 條明訂遇到就先暫停回報的情況。
