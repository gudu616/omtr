# 09. Gold Logprob（黃金對數機率）：記憶強度尺

**一句話白話版**：gold_logprob 是「把正確答案的原文，用『老師逼你照著念』的方式念一遍，看模型對每個字的信心有多高」——不是問模型「你自己接不接得出這句話」，而是問模型「如果我把答案攤開給你看，你會不會覺得『對，就是這個字』」。信心越高（數字越接近 0）代表背得越熟。

**為什麼本研究用得到**：語料計數（模型的教材裡某段話出現幾次）只能告訴我們「模型有沒有機會看過」，不能告訴我們「模型真的記住了多少」。gold_logprob 是連續的「記憶強度」量尺，可以跟收斂深度、熵一起做卡 08 提到的劑量反應分析，這比把題目硬分成「背過／沒背過」兩個籃子精確得多。

**再深一點**：teacher forcing（老師逼供式生成）的白話版：正常生成時，模型是「自己選一個詞、把這個詞餵回去、再選下一個」，一步錯就步步錯，量出來的是「模型自己能不能一路接對」；teacher forcing 反過來——不管模型上一步猜的是什麼，永遠把「真正的原文」塞給它當上文，只問「在看到正確上文的前提下，你給正確的下一個字打幾分機率」。`harness/run_pilot.py` 的 `gold_logprob()` 函式做的正是這件事：把 `prompt + gold` 一次餵給模型跑 forward（不是逐字生成），對答案區間的每個位置取「模型給真正下一個字的 log 機率」，再取平均（`per_tok[n_prompt - 1:].mean()`）。算出來的數字必然 ≤ 0：越接近 0（例如 −0.05）代表模型幾乎把全部信心都押在正確的那個字上；越負（例如 −3 以下）代表模型認為正確答案是個相對意外的選擇。函式一開始還有個防呆：把 `prompt+gold` 重新斷詞後，如果跟原本 `prompt` 斷出來的 token 前綴對不上，就整筆標記 `tokenization_boundary_mismatch` 放棄——因為 tokenizer 有時會把 `prompt` 結尾和 `gold` 開頭的字元黏成不同的 token，若不擋掉，量到的位置就會全部錯位。

**在我們的程式碼／數據裡**：最乾淨的反例是 battery 裡的 `L0-01`——《傲慢與偏見》開頭那句「It is a truth universally acknowledged...」。它在 Pythia 的教材（Pile）裡驗證出多個片段各出現 6～171 次（`battery/l0_verification.json`）——多數窗口遠超收錄門檻（最高 171；`harness/verify_battery.py` 的 `L0_COUNT_THRESHOLD = 20`），仍有兩個跨句窗口只有 6，靠「至少 70% 窗口 count ≥ 20」的規則通過，照語料計數看應該是背得很熟的一句。但在煙霧測試的實際紀錄（`results/smoke/pilot_EleutherAI_pythia-1.4b.json`，id `L0-01`）裡，Pythia 的貪婪生成（`greedy_continuation`）接出來的是「is so generally known, that it is not necessary to enter into particulars.」——完全不是原文「well fixed in the minds of the surrounding families...」，而它的 `gold_logprob_per_token` 只有 −1.69，遠不如同一批資料裡其他真正背熟片段常見的 −0.05 到 −0.15 這種接近 0 的分數（見 `results/analysis_EleutherAI_pythia-1.4b.json` 的 `dose_response.points`）。「教材裡出現很多次」跟「模型真的把那句話刻在骨子裡」是兩回事——這正是我們捨棄「語料計數二分法」、改用 gold_logprob 當連續量尺的直接理由。

**常見誤解**：
1. 「gold_logprob 就是模型自己會不會接出這句話」——不是。模型自己接（貪婪生成）跟 gold_logprob 是兩件不同的事：即使模型自己接不出原文（如上例），只要在「被告知正確上文」的前提下對正確的下一個字給出高機率，gold_logprob 還是可能不低；反過來也可能發生模型自己剛好矇對、但逐位置信心其實普普通通。兩者要合起來看才完整。
2. 「教材出現次數多就代表背得熟」——語料計數只回答「模型有沒有機會看過幾次」，不回答「權重裡到底有沒有把這段話焊死」；上面《傲慢與偏見》的例子就是最好的反證。

**答辯模擬題**：
- Q：為什麼不直接用模型自己生成的文字去跟原文比對重疊字數就好？
  A：那樣量到的是「模型自己選字鏈條有沒有一路踩對」，一步偏掉語意就跟原文差很遠，訊號會很粗糙、近乎二元。teacher forcing 每一步都用真正的原文重新當上文問一次，量到的是更細緻的逐字信心，不會被單一步的偏差拖累後面所有分數。
- Q：gold_logprob 永遠是負的，要怎麼判斷「多負算低」？
  A：我們不是看絕對數字判斷單一題目，而是把它當連續變量跟其他指標做劑量反應相關分析——例如全樣本 rho = −0.29（p = 0.0355，n = 53，見卡 08）。它的高低順序、和其他指標的相關方向，比孤立的某個數字更有意義。
