# 11. 對照組與混淆變因（Control Group & Confound）

**一句話白話版**：光看「模型能接出背過的名段」證明不了記憶——這句話本身可能只是文法工整、好猜；L0N 就是另外找一段文長、文體、年代全部一樣，但幾乎沒被模型讀過的冷門段落來當比較基準，把「有沒有背過」這一個變因單獨挑出來。

**為什麼本研究用得到**：本研究要宣稱「回憶跟創造在模型內部長得不一樣」，但如果只比 L0（背名段）跟 L5（發明新東西），兩者除了「有沒有背過」還同時差了十幾樣東西：句子長短、文體工整度、要不要遵守格式……這些同時在變、混在一起、分不清是誰造成差異的變數，叫混淆變因（confound）。不把記憶單獨隔出來測，量到的差異可能整個是這些混淆造成的，不是記憶造成的。

**再深一點**：`harness/build_l0_controls.py` 從冷門近年 Gutenberg 電子書的深處（`WORD_OFFSET=1500`，刻意避開最常被引用的開頭）切出段落，沿用同樣的 88 詞、44 詞切分常數，但沒有套 L0 的 `shift_split()` 實詞位移（L0 實際切在第 44–47 詞、邊界一定是實詞；L0N 固定切在第 44 詞、邊界可能是虛詞——這是目前對照組唯一已知的未配平差異，方向上會讓 L0N 的第一個 token 更受句法決定，解讀 L0/L0N 差異時必須把它算進去）。它跟 L0 之間主要的差異仍是：這段話有沒有在模型的訓練語料裡出現過大量次數，交給 `harness/verify_battery.py` 的 `--mode control` 驗證（`CONTROL_MAX_COUNT=2`，門檻反過來要求「幾乎查無」）。有了這組配對，L0 的內部訊號如果顯著跟 L0N 不一樣，才能歸因給記憶，而不是文體或長度。

**在我們的程式碼／數據裡**：`build_l0_controls.py` 的 `looks_english_prose()`（篩掉非英文或格式怪異的段落）與 `CANDIDATE_IDS`（刻意挑書號很大、近年才收錄的冷門候選書）。第一批 pilot 數據（`docs/PROCESS_LOG.md` 第十二步）證實了這組對照有分辨力：同樣接續古典散文，「背過的」L0 比「沒背過的」L0N 熵低很多（效應量 −0.627，OLMo −0.845）；收斂深度的效應則對門檻敏感——tau 0.1 為 −0.368、tau 0.05 −0.221、tau 0.5 −0.167，argmax 版本效應量很小、接近零（−0.044，方向仍與其他門檻一致、不是反向），絕對差距同樣不大（tau 0.1 下 0.9335 vs 0.9470，24 層約 0.3 層），所以「背過的更早定案」目前只算方向性線索，穩健的是熵，深度要等更大樣本與更多門檻一致才敢主張——這正是當初審查逼我們加對照組的原因。

**常見誤解**：
1. 「L0N 只是湊數，反正都是古典散文，效果應該差不多」——如果真的差不多，代表研究出了問題：L0/L0N 之間的差異正是這個研究要抓的訊號，不同才是研究成立的證據。
2. 「control 挑不同段落就好，不用管長度」——長度、句法本身也會影響內部訊號（熵天生隨句長緩慢上升），L0N 若比 L0 長兩倍，測到的差異又混進了長度效應，回到混淆變因的老問題——所以 L0N 沿用 L0 同一組 `TOTAL_WORDS`/`SPLIT_AT` 常數。

**答辯模擬題**：
- Q：如果沒有 L0N，這個研究的結論會有什麼問題？
  A：任何「回憶題內部訊號跟創造題不同」的結果，都可能只是「短的、工整的古典句子比較好猜」造成的，跟模型有沒有真的記住這段話無關——這叫混淆，會讓核心結論站不住腳。
- Q：為什麼 L0N 特別選近年、冷門、書號很大的書，不用隨便一本舊書？
  A：舊書、名著本身也有機率被模型讀過或被大量轉載引用；選近年、冷門的 Gutenberg 電子書是刻意壓低「不小心也被背到」的機率，讓對照組乾淨。
