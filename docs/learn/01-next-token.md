# 01. 下一個詞預測（Next-token Prediction）

**一句話白話版**：LLM（大型語言模型，本研究測試的 AI）從頭到尾只做一件事：看著目前為止出現過的文字，猜「接下來最可能出現的一個詞是什麼」，把猜到的詞接上去，然後把這串變長的文字當成新的「目前為止」，再猜一次。不管你要它「背出《傲慢與偏見》開頭」還是「發明一款新門鈴」，它執行的動作完全相同，只是重複的次數、和每次猜出來的東西不一樣。

**為什麼本研究用得到**：本研究要問的問題——「回憶」和「創造」是不是共用同一套內部機制——之所以問得成立，前提正是：從外部看，這兩件事本來就是同一個動作（下一個詞預測）反覆執行的結果，兩者共用同一條計算路徑（forward pass，模型從輸入到輸出跑一次計算的完整過程）這件事沒有懸念。`README.md` 講得很直接：「不是『有沒有共同內部現象』（同一條 forward pass，答案必然是有），而是：」——後面接的才是我們真正要用實驗回答的三個假說（見卡 15）。如果外部這層共用都不成立，整個研究的提問方式就會垮掉，所以這張卡是全部後續卡片的地基。

**再深一點**：更精確地說，模型不是「直接猜一個詞」，而是替詞彙表裡**每一個**候選詞都算出一個分數（logits，還沒轉成機率之前的原始分數），再轉成機率分布，機率最高的那個就是它「想」接的下一個詞。訓練的時候，模型只被教一件事：看過的文字裡，下一個實際出現的詞，把它的機率調高一點，這樣調整幾兆次。背《傲慢與偏見》開頭時，模型的機率分布因為訓練時看過這段文字非常多次，變得又高又尖——幾乎只有一個詞的機率接近 100%；發明新點子時，同一套「算機率、選最高分」的機制仍在運作，只是這次機率分布比較平坦、好幾個詞都有機會。回憶和創造表面上完全一樣，差別只在機率分布的「形狀」。

**在我們的程式碼／數據裡**：`harness/run_pilot.py` 的 `run_item()` 函式裡，不論題目是 L0（逐字背誦）還是 L5（自由發明），都經過同一行程式碼——`model.generate(tokens, max_new_tokens=gen_tokens, do_sample=False, verbose=False)`（第 170–171 行）。這一行做的正是「每次都選分數最高的下一個詞、接上去、再猜下一個」，六階任務階梯＋一組 L0N 對照（L0、L0N、L1–L5，共七個條件）全部共用同一個生成迴圈，程式裡沒有替任何一個層級寫過「背誦模式」的特殊分支。另外 `gold_logprob()` 函式（第 136–147 行）把「模型對正確答案這串詞，逐步給出的下一個詞信心」平均起來，變成一把連續的「記憶強度尺」（細節見卡 09）。

**常見誤解**：
1. 「模型是先想好整句話的意思，再把它拆成字講出來」——不對。模型沒有「先想好全句」這個步驟，它是一個詞接一個詞往前生成，連自己第 5 個詞會是什麼，在生成第 3 個詞的當下都還沒決定。這正是 logit lens（卡 06 會細講的量測方法，中途攔截「還沒寫完」的暫定答案）有意義的原因。
2. 「回憶和創造在模型裡走的是不同電路，所以才有這個研究」——這是我們要**驗證**的東西，不是預設的前提。目前唯一確定的是兩者外部呼叫同一個函式、同一套生成機制；內部有沒有分流，正是卡 15 要裁決的三個假說之一。

**答辯模擬題**：
- Q：你們怎麼確定回憶和創造真的是「同一個動作」，不是自己假設出來的？
  A：這不是假設，是這類模型的架構事實——不管題目難度，程式呼叫的都是同一個 `model.generate` 函式、同一套「算機率、選詞、接上去」的迴圈，沒有替任何任務類型寫過特殊分支。我們要研究的是這個共用動作的**內部**訊號在兩種任務下是否不同，不是外部有沒有共用（外部一定共用，這點沒有爭議）。
- Q：如果下一個詞預測這麼簡單，模型怎麼會「創造」出新東西？
  A：因為機率分布不是只有一個答案。背誦題的分布被訓練得又高又尖，幾乎鎖死一個詞；創造題的分布比較平，好幾個詞都有不低的機率，模型每一步選到的組合湊起來就是「新東西」。創造不是另一套機制，是同一套機制在機率分布比較平坦時運作的結果——這正是本研究三個假說之一（regime 假說，見卡 15）要驗證的內容。
