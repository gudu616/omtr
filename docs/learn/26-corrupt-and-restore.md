# 26. 腐蝕-恢復 patching（Corrupt-and-Restore Patching）

**一句話白話版**：想知道書桌上少掉一塊餅乾是不是因為某個特定原因，光在旁邊「看」沒有用——你得主動做實驗：先故意弄壞一個東西（把提示句裡一個關鍵詞換掉，讓模型的答案變差、變得不篤定），再把「健康版本」當時腦中在某一層的狀態整段複製貼回去，最後量：**貼回去之後，答案恢復了幾成？**這整套「弄壞→貼回去→量恢復」的動作，就是這張卡要講的東西（原文叫 patching，這裡照本研究的說法譯成「腐蝕-恢復」）。

**為什麼本研究用得到**：因果階段要拆解「背過的題」跟「單純好猜的題」在模型內部走的是不是不同的路。光靠觀察（logit lens、熵、KL 收斂深度——見卡 06、07、08）只能說「兩者看起來不一樣」，說不出「這個不一樣是被什麼造成的」。要證明因果，就得干預：弄壞一個線索詞、把乾淨版本某一層的狀態貼回去、量恢復了多少。這是研究從上一期（v0.7）的純觀察，進到因果階段的關鍵工具。

**再深一點**：具體動作分四步（`CAUSAL_PREREG_v1.md` §2）。
1. **腐蝕**：把提示句裡一個真實英文詞換成另一個真實英文詞（STR 式），換完之後 token 數量、位置都要對齊，只是那一個詞不一樣。
2. **校準強度**：不是隨便換一個詞就好——換太輕沒效果、換太重會把模型徹底打亂。程式會試很多個候選替換詞，只留下「真的讓答案變差」的那些（drop = 清醒版 − 腐蝕版的 gold 機率，drop 必須是正的），再從裡面選一個中等強度的。
3. **貼回去（patch）**：從同一題「沒被腐蝕過的乾淨版本」（叫 donor，捐贈者）裡，把它某一層、cue 詞附近幾個位置的內部狀態，複製貼到腐蝕版本的同一個位置上——注意 donor 是**同一題自己**的乾淨狀態，不是另一題的。
4. **量恢復**：算恢復比例 R = (貼回去的答案 − 腐蝕版答案) / (乾淨版答案 − 腐蝕版答案)。R 接近 1 代表「貼回去幾乎完全救回原本的確定度」，R 接近 0 代表「貼了也沒用」。

有兩種不同的「答案」可以拿來量：一種是**餵給模型正確答案，問它信不信**（teacher-forced，也就是主要終點：起手窗前兩個 token 的 gold 機率）；另一種是**放手讓模型自己寫**，看它寫出來的東西跟原文重不重疊（自由續寫溯源軌）。這兩種是不同的量——模型可能覺得「這段話很像」機率很高，卻永遠不會真的自己寫出一模一樣的字，因為自己生成的路一旦岔開就回不去了。所以兩軌都要看，缺一不可（見 `theory_v3_final.md` N-f.4）。

**在我們的程式碼／數據裡**：`harness/causal_patch.py` 的 `calibrate_corruption`（選腐蝕強度，含「只留 drop>0」的守門規則）、`cue_neighborhood`（貼回去的位置範圍）、`patched_readout`（真正做貼回去這件事）、`recovery_ratio`（算 R）；規格見 `planning/CAUSAL_PREREG_v1.md` §2、§7；建置過程的踩坑記錄在 `planning/rig_build_report.md` §3.5（第一版校準規則挑到「讓 gold 變好」的腐蝕，已修）。

**常見誤解**：
1. 「只要貼回去就是 patching，弄壞的部分不重要」——不對。如果弄壞的方式本身讓答案變好（drop ≤ 0），那筆資料不算數，不能進任何分析。本研究真的踩到這個坑：舊版規則按絕對值排序選腐蝕，結果兩題選到了「腐蝕」反而讓模型更確定答案的候選，已改成「只有真的弄壞（drop>0）的候選才有資格」。
2. 「貼回去的是答案文字」——不對，貼回去的是模型內部某一層的向量狀態（一串數字），不是把答案塞進去。

**答辯模擬題**：
- Q：為什麼不直接看模型自然回答就好，一定要弄壞再修？
  A：因為單純觀察分不出「這個現象是不是那個線索造成的」。弄壞、修復、量恢復多少，才是因果實驗的標準做法——這是主動干預，不是被動觀察。
- Q：貼回去的東西是整段對話嗎？
  A：不是，是模型內部某一層、cue 詞附近幾個位置的向量狀態，而且來源（donor）是同一題自己的乾淨版本跑出來的，不是另一題的。
