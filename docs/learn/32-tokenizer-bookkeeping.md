# 32. Tokenizer 的記帳方式：同一句話，兩家算的帳不一樣

## 生活場景

兩家超市賣同一箱飲料。A 超市的發票把「箱子」算一件商品，B 超市不算。
你拿著 A 的發票去 B 對帳，永遠差一件——**東西沒少，是記帳方式不同**。

## 這次撞到的兩顆地雷

模型把句子切成一個個小塊（token）。我們要把「第幾塊」對到「原文第幾個
字」，結果發現**每家模型的記帳慣例不一樣**，而且有兩個獨立的差異：

1. **開頭墊不墊起始記號（BOS）**：OLMo 會在句子最前面墊一塊「開始」
   記號，Pythia 家族不墊。差一塊，後面所有編號全部錯位。
2. **詞前面的空格算誰的**：英文的詞前面常有空格。OLMo 把空格算進
   那個詞的地盤，Pythia 不算。對位置時又差一個字元。

我們的凍結規格把其中一家的慣例當成了「全世界都這樣」，寫成通用公式
——結果程式的自我檢查在另外四個模型上全部炸掉。

## 怎麼修才不算「看資料改規則」

不是把公式改成另一個猜測，是**把「有沒有墊」變成量出來的**：
兩個長度一減，差只能是 0 或 1，其他值程式直接停機。判斷空間為零，
所以修了規格也沒有給任何人「挑對自己有利」的機會。

## 帶走的一句話

**「大家都這樣」是最危險的一種話——尤其當它寫在一個標了出處的段落裡，
而那個出處其實沒講過這句。** 逐模型的事實要逐模型量，不能用印象推。
