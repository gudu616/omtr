# 25. 文獻檢索的紀律（Literature Search）

**一句話白話版**：查文獻是兩段式的——先用摘要**大量篩選**（這一步快而且可以粗），再對少數幾篇**全文精讀下判定**（這一步慢而且不准偷工）。整個紀律的核心是一句話：**摘要只能決定「要不要讀」，永遠不能決定「這個方向死了沒」。**

**為什麼本研究用得到**：這個專案的前身被八輪文獻檢索殺掉四個方向，靠的正是這套流程；而它也實測抓到**六次**「搜尋摘要／AI 轉述層把不存在的內容歸給論文」——其中一次捏造出三個子句、各有機制、逐字命中當時正在評估的假設；另一次同一句定義四次抓取得到四個不同版本。如果當時憑摘要下判定，會做出建立在幻覺上的決策。因果階段的設計（本期）由八篇全文精讀撐起，每一篇的載重引文都用本地下載的原始檔逐句 grep 核對過。

**再深一點**：

*怎麼下查詢字串*——把你的問題拆成幾個「軸」（例如：方法軸 activation patching、對象軸 memorization、對照軸 predictability confound），每軸列同義詞，交叉組合去搜。搜過的字串**全部留檔**：這讓下一個人（包括未來的你）能重現你的檢索、補你的漏，也是「我真的查過」的證據。本期文獻部留了 20 條字串在 `planning/office_reports/lit_reading_list.md` 檔尾，可當範本。

*威脅分級*——篩出來的論文不要平鋪，按「這篇如果全文屬實，多大機會殺死我們的方向」排序，最危險的先精讀。你的時間有限，先讀可能判你死刑的，不是先讀最有名的。

*可查證問題*——精讀前先把問題寫成**可以逐字查證**的形式：「這篇有沒有做可預測度配平的對照？第幾節？數字多少？」而不是「這篇在講什麼？」。後者正是會被捏造內容騙過去的問法。查無就寫 **NOT PRESENT**，不准用推論補完。

*全文哪裡拿*——arXiv 論文試 `arxiv.org/html/編號`（新論文多半有 HTML 版），沒有就試 `ar5iv.labs.arxiv.org/html/編號`，再沒有才啃 PDF。**把原始檔下載到本地存檔**：之後任何引文有疑義，都能用搜尋逐字核對，這是對付轉述層捏造的最終防線。

*判定的措辭階梯*——只讀過摘要：最多說「看起來很近，待確認」。讀過全文且查證過：才能說「此方向已被做過」或「缺口存在（NOT PRESENT）」。撤回自己的話跟下判定用同一標準：不准用沒查證的東西推翻已查證的結論。

**在我們的程式碼／數據裡**：本期的實物範例都在 `planning/office_reports/`——`lit_reading_list.md`（14 篇三級威脅清單、每篇附可查證問題、20 條查詢字串）、`fulltext/*.md`（八篇精讀，逐字引用＋節號＋NOT PRESENT 標記）、`fulltext/verification_log.md`（每篇的本地快照逐句核對記錄，含一次現場抓到轉述層捏造的完整事件：四抓四版本、自相矛盾的表格描述、一條只出現一次的疑似杜撰公式）。

**常見誤解**：
1. 「Google 的 AI 摘要／搜尋結果片段算讀過」——不算。本專案的規矩：搜尋摘要、AI 摘要、arXiv abstract，**三個都不算讀過**。它們的用途只有一個：決定值不值得花時間拿全文。
2. 「查到 GitHub issue 或部落格講過這個問題，就代表這個研究問題被回答了」——「有人碰過這個問題」和「這個問題被科學地回答了」是兩回事，不可混為一談。
3. 「找到相近的論文＝方向死了」——要看它做的跟你要做的差在哪，而且差異要用**它的全文**來界定，不是用你的期望。反過來也一樣：不准用「但我的角度不一樣」幫已經被做死的方向續命——差異要具體到對照組、量測、樣本的層級才算數。

**答辯模擬題**：
- Q：你們的文獻檢索怎麼保證沒有漏掉關鍵論文？
  A：不保證，也沒有人能保證——我們自己量過，光一個小生態位就用了 20 條查詢字串加八篇全文，還是留了三個明標「未查」的方向。我們保證的是三件可檢查的事：查詢字串全部留檔（可重現、可補查）、每個「已被做過／缺口存在」的判定都有全文精讀與逐字引用支撐、查不到的明寫 NOT PRESENT 而不是假裝查過。
- Q：為什麼不直接讓 AI 讀論文給你聽就好？
  A：因為我們實測抓到六次 AI 轉述層對論文內容的捏造，其中一次逐字命中我們正在評估的假設——那種捏造無法靠「聽起來合理」識破，只能靠拿原始全文逐字核對。AI 可以幫忙抓檔案、幫忙核對，但「這篇論文說了什麼」的最終判定，必須建立在有人（或有程序）碰過原始文本上。
