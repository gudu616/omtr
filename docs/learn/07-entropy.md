# 07. 熵（Entropy）

**一句話白話版**：熵是一支「猶豫程度溫度計」。把模型在某一層當下的整個詞彙機率分布攤開來看——如果它幾乎把全部信心都押在一個詞上，熵就趨近 0（毫不猶豫）；如果它在一堆詞之間平均分散注意力，熵就很高（完全沒把握）。

**為什麼本研究用得到**：我們的核心假說之一是「回憶時篤定、創造時猶豫」。熵正是量化「篤定 vs 猶豫」最直接的工具，而且可以在每一層都算一次，畫出「猶豫程度隨層數變化」的曲線，跟卡 06 的 logit lens 搭配使用——logit lens 告訴你「這一層暫定答案是誰」，熵告訴你「這一層有多相信這個暫定答案」。

**再深一點**：熵的公式白話講：把每個候選詞的機率 p 拿去乘上 −log(p)，再全部加總。直覺理解：一個詞機率越低，−log(p) 就越大，代表「這個詞出現有多讓人意外」；熵就是「用機率加權後，平均起來有多意外」——也就是整個分布的平均意外程度。如果模型只押一個詞（機率 = 1），意外程度是 0；如果在幾萬個候選詞裡完全隨機亂猜，意外程度會逼近詞彙表大小的對數。熵的單位是 nats（因為我們全程用自然對數 log_softmax，見卡 06 的 `Fp32Lens`），數值可以遠大於 1，不是介於 0～1 之間的機率。

**在我們的程式碼／數據裡**：`harness/run_pilot.py` 的 `position_profile()` 對每一層計算 `entropy = -(p * logp).sum()`（fp32、log_softmax 為底，跟 logit lens 共用同一份高精度翻譯器）。真實數字來自 `results/analysis_EleutherAI_pythia-1.4b.json` 的 `levels.*.final_entropy_mean.mean`：L0（逐字背誦）1.74 → L1（常識回想）2.61 → L2（改寫）2.78 → L3（格式創作）3.58 → L4（強迫混搭）4.13 → L5（自由發明）4.25；對照組 L0N 是 3.584，已經追平甚至略高於 L3 的 3.579、落在 L3 與 L4 之間——它不是階梯的一階，只是拿來跟 L0 配對比較的對照，但它的位置也提醒我們：階梯不是純粹的記憶軸，沒背過的古典散文的不確定程度甚至超過了格式創作（L3）。從純回憶到純創造，熵幾乎單調上升——這正是任務階梯設計想看到的漸變信號，也是目前七個條件裡最乾淨、排序最符合設計預期的一條曲線。但要注意 L0/L0N/L1 與 L2–L5 屬不同 prompt 家族（prompt token 中位數 50–60 vs 201–408），跨家族的熵差含格式與長度成分，最強的證據仍是家族內對比（L0 vs L0N、L1 vs L4）。

**常見誤解**：
1. 「熵高 = 模型比較笨、答錯了」——不對。熵高只代表模型面前有很多同樣合理的選項（例如「寫一首關於火星的俳句」本來就有無限種寫法），是任務本身開放度高的訊號，不是能力不足。
2. 「熵是一種機率」——不是。熵是用機率算出來的「不確定性」數值，可以大於 1、甚至到十幾（取決於詞彙表大小和分布形狀），跟 0～1 之間的機率是完全不同量綱的東西。

**答辯模擬題**：
- Q：為什麼不直接看模型輸出的機率就好，要多算一個熵？
  A：單一詞的機率只告訴你「這個詞有多被看好」，看不出「除了這個詞之外，模型還把賭注押在多少其他詞上」。熵把整個分布的猶豫程度收斂成一個數字，才能拿六個難度層放在同一把尺上比較、畫出漸變曲線。
- Q：熵從 1.74 升到 4.25，這個差距算大嗎？
  A：熵是對數尺度：每多 1，大約代表模型心裡多考慮了 e≈2.7 倍的等效選項數。從 1.74 到 4.25 差了 2.5，換算下來相當於創造題時模型認真考慮的候選詞規模是背誦題的十幾倍——而且是六層平滑遞增，不是一次跳躍，這比單一個大數字更有說服力。
