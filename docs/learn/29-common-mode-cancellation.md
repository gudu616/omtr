# 29. 共模抵消與它的失效（Common-Mode Cancellation）

**一句話白話版**：你有兩支溫度計，一支放冰箱裡的優格、一支放旁邊的牛奶，兩支溫度計都有一點系統性偏差（比如都偏高 0.5 度）。如果你要量的是「優格跟牛奶的溫差」，只要兩支溫度計的偏差差不多大，相減之後偏差會自己抵消掉大半，量到的溫差還是準的——這叫**共模抵消**。但這招有個前提：兩邊的偏差要「差不多大」。**如果换一台冰箱（換一個更大的模型），偏差可能一支變大很多、另一支沒有，相減就抵消不掉了。**

**為什麼本研究用得到**：這正是研究裡一次真實發生、又被自己抓到的推翻事件（J6→J7）的核心。理論部原本推論：fp16（半精度浮點數，見卡 28）換 fp32 的浮點誤差，雖然單次前向的偏差不小（0.118 nats），但因為配對比較的兩邊輸入幾乎一樣，相減之後（共模抵消）DiD（雙重差分，兩組差距再相減一次）只剩 0.011——只有 MDE（能偵測到的最小效應）的 4%，可以放心用 fp16 跑。而且推論「這個機制（共模抵消）跟模型大小無關」。**但這句話只在 1b 模型上量過。**之後補量 1.4b，DiD 一口氣跳到 0.240——是 MDE 的 87%，幾乎命中原本被撤回的「最壞情況」推算值 0.236。兩個模型差 22 倍，直接打臉「機制與大小無關」這句話。

**再深一點**：共模抵消為什麼會發生：如果兩個測量的「系統誤差」高度相關（來自同一個原因、方向大小都接近），相減就會把共同的那部分消掉，只留下差異的部分。這裡的「系統誤差」是 fp16 算術在每次前向累積的浮動誤差；因為配對比較的兩題輸入非常相似（同一題的乾淨版跟腐蝕版，只差一個詞），理論上兩邊吃到的浮點誤差性質也很像，相減之後應該消掉大部分。1b 上量到的 0.011 nats，正是這個抵消發生的證據。

但「機制存在」不等於「機制的大小跟模型無關」。1.4b 上量到 0.240，說明抵消的效果在更大的模型上大幅減弱——具體是哪個環節失效（誤差不再共模、或誤差本身在大模型上不成比例放大）沒有被進一步拆解，只知道「不能外推」。這件事直接催生了卡 30 講的那條新規矩：任何跨模型外推的參數，至少要在兩個相隔一個量級的模型上量過，才能拿來做判定的依據。理論部自己在報告裡認錯：「我讓一條標了〔推〕的話去承載一個定版決定」——這正是「讀來的／推論的東西比量出來的更容易錯」這條專案規律的又一次實例。

最終裁定不是「多量幾個模型湊合著用」，而是**把問題直接消滅**：四個裝得進 8GB 顯卡的模型全部改用 fp32 跑（跑 fp32 就沒有 fp16 偏差可言，不需要量它、不需要為它掛限定語），只有裝不進 fp32 的 2.8b，另外用 CPU 跑 fp32 量它自己的偏差來決定去留，而不是把 1b/1.4b 的數字硬套在它身上。

**在我們的程式碼／數據裡**：`planning/office_reports/theory_v3_final.md` 附錄 J（J1–J7，尤其 J6「兩個推翻工單前提的發現」與 J7「緊急重裁」）；`diag_j4_dtype_did.json`（1b 實測數據）；1.4b 的對應診斷檔記在 J7 表格裡；最終裁定見 J7 (a)(c)：四個模型改 fp32、2.8b 用 CPU fp32 量自己的門檻決定去留。

**常見誤解**：
1. 「共模抵消是個穩定的物理定律，量一次就能用在所有模型上」——不對，它依賴「兩邊系統誤差高度相關」這個經驗前提，前提本身可能隨模型大小改變，必須逐模型驗證，不能只驗一個就當通則。
2. 「1b 量到很小，所以 fp16 在這個研究裡都安全」——這正是被推翻的那句話，1.4b 的量測直接打臉這個外推。

**答辯模擬題**：
- Q：你們一開始的結論（共模抵消讓 fp16 安全）後來被推翻，這會不會讓人質疑你們的其他結論也不可靠？
  A：恰恰相反——這正是「量測必須覆蓋足夠範圍才能承載判定」這條紀律被自己的資料抓到的例子。我們沒有把第一次的推論（基於單一模型）直接寫進最終結論，而是繼續在下一個模型上驗證，量到不一樣就照實撤回、公開記錄推翻的過程，並把教訓提升成制度。這比「維持原判不覆核」可信。
- Q：為什麼不乾脆一開始就在所有模型上都量過，省得後面被打臉？
  A：因為窗口 A 的冒煙資源有限，一開始只在一個模型上驗證是合理的成本控制；真正的錯不是「只量了一個模型」，是把那個結果講成「機制與模型大小無關」——一個外推的推論被寫成了定版判斷。修法不是每次都全量，是把「這個結論只驗過幾個點」如實標記，不足時就不承載判定。
