# 24. 裁決規則的可點燃性（Decision-Rule Reachability）

**一句話白話版**：預註冊會先寫好幾個「出口」——結果長這樣就走 A 門,長那樣就走 B 門。但門寫出來不代表打得開:如果某個門的開門條件在數學上幾乎不可能成立,那實驗跑完最可能的結局是「站在走廊裡,哪個門都沒開」。在花錢跑實驗**之前**,應該先用模擬檢查每個門在各種真相下的開門機率——這叫檢查裁決規則的可點燃性。

**為什麼本研究用得到**：L0P 預註冊寫了三個出口:R-memo（記憶專屬成分存活）、R-generic（效應是一般可預測性）、R-failed（操縱失敗）。解盲前的對抗式審查用模擬發現:R-generic 要求「4+ 個 run 無一致符號」,但四個 Pythia 模型共用同一批題目,它們的係數符號天生同進同退——所以「無一致符號」幾乎永遠不成立,**不論真相是什麼**。預註冊防了一致的負號（記憶方向）,沒想到一致的正號同樣會把 R-generic 擋死。實跑結果正是這個劇本:五個符號全部一致（而且是正的）,裁決落在「無規則點燃」。這不是資料的錯,是預註冊自己寫進去的結構,v0.7 如實把它當成一個設計錯誤發表。

**再深一點**：為什麼「共用題目」會讓「無一致符號」變成打不開的門?想像四個評審看**同一批**考卷打分數:就算評審之間毫無默契,他們的分數也會高度相關,因為考卷本身的好壞是共同的。要求「四個評審意見分歧」等於要求「同一批考卷在不同人眼裡好壞相反」——幾乎不會發生。正確的做法是把出口定義在**獨立的證據單位**上:這裡真正獨立的單位不是「五個 run」,是「兩個語料家族」（Pythia 系 vs OLMo）,或者乾脆用合併統計量的信賴區間來寫出口。另一個教訓是「none 裁決」的價值:它逼你誠實說「裁決未出」,而不是把沒過關的型態事後包裝成「傾向支持某某」——這正是預先凍結敘述（把每個出口的說法在解盲前逐字寫死）要守住的東西。

**在我們的程式碼／數據裡**：預註冊 `docs/PREREG_L0P.md` §Decision rules;裁決實作 `harness/l0p_analysis.py` 的 `verdict()`（逐字照預註冊,包括這個打不開的門——預註冊凍結後連保守方向的偏離都不准）;可點燃性模擬是對造律師（審查代理）在解盲前跑的:R-generic 為真的世界裡,本設計約三分之二機率回報「無規則點燃」（量值出自未經真資料校準的生成器,只引方向）。實跑結果 `results/l0p/l0p_analysis.json` 的 `verdict.rule = "none"`;解盲前凍結的各出口敘述在 `docs/PROCESS_LOG.md` 第二十三步。

**常見誤解**：
1. 「裁決是 none,所以實驗白做了」——不對。這次實驗量到了兩個扎實的東西:劑量反應在零暴露文本上以幾乎同樣強度重現（rho −0.71 到 −0.77,五個 run）,以及配平之後偵測不到記憶專屬的銳利化。「none」只是說這兩個觀察沒有走進任何一個預先寫好的門;v0.6 留下的識別缺口從「懸而未論」變成「被量過但未解決」,下一步的設計因此有了明確的靶。
2. 「早知道會 none,當初把 R-generic 的條件放寬就好」——解盲**之後**放寬條件,等於把門重新裝在資料已經站的位置上,那預註冊就白簽了。正確的時間點是下一次預註冊:把出口定義在獨立證據單位上,並在送出前先跑一輪可點燃性模擬。

**答辯模擬題**：
- Q：你們的預註冊有設計錯誤,那整份結果還可信嗎?
  A：分兩層。數字這一層完全不受影響——A1/A2/A3 的每個統計量都照凍結規格算,能被對帳閘門從原始資料重算。受影響的是「裁決」這一層:有個出口在數學上幾乎打不開,所以「無規則點燃」的資訊量比表面上低。我們的處理是把設計錯誤本身如實發表（含發現它的時間點:解盲之前）,並承諾下一次預註冊把出口定義在獨立證據單位上。發現自己的預註冊有洞而且照規則走完,比事後改規則可信。
- Q：為什麼不乾脆在解盲前修掉這個門?審查代理不是已經發現了嗎?
  A：因為預註冊已經公開上鏈（commit 459710c）,它的價值就在「事後不能動」。解盲前我們能做、也做了的是:把每個可能結局的**說法**逐字凍結（包括 none 的說法）,讓事後的敘述空間歸零。改規則會毀掉時間戳的意義;凍結敘述則是在不動規則的前提下,把「事後包裝」這條路也堵死。
