# 03. Base 模型與 Instruct 模型（Base vs Instruct）

**一句話白話版**：我們研究用的兩個模型（Pythia-1.4B、OLMo-2-1B）都是「base 模型」——意思是它們只被教過「接下去寫」，從來沒有被額外教過「聽懂使用者在問問題、乖乖回答」這件事。你問它「蜜蜂替植物傳什麼？」，它不見得會回答你，反而可能把你的問題當成一段網路文章的開頭，接著模仿網路文章常見的排版往下寫。

**為什麼本研究用得到**：這件事直接決定了整份題庫該怎麼設計。如果模型根本不「回答問題」而是「接續文字」，那我們就不能用日常對話的問法出題，否則量到的訊號會被「模型在猜這是哪種文章、接下來該長什麼樣子」污染，而不是我們真正想量的「模型有沒有記得或編出正確答案」。這也是為什麼 L1（事實回想）題目最後全部改成卡 05 要講的「接話」（cloze）格式——這個決定不是憑空來的，是實測撞到問題後才確立的。

**再深一點**：「聽指令」不是語言模型天生就會的能力，是額外訓練出來的（業界稱為 instruction tuning，指令微調）：先讓模型看過大量「使用者問—助理答」的對話範例，再用人類回饋去調整，讓它學會「看到問題就該直接回答、看到指令就該照做」這種特定的行為模式。我們刻意選沒有做過這一步的 base 模型，是因為 base 模型的訓練資料和輸出行為都更貼近「純粹的下一個詞預測」（卡 01），而且——這點對本研究特別關鍵——base 模型的訓練語料完全公開，才能用 infini-gram（卡 14）查出它到底背過什麼。代價是：base 模型不會「配合」你的提問格式，你要用它熟悉的文字形狀跟它說話，它才會給出你要的東西。

**在我們的程式碼／數據裡**：`docs/PROCESS_LOG.md` 第十步記錄了這個問題第一次被撞見的實況：早期題庫（v1）用直接提問的格式，`results/smoke/pilot_EleutherAI_pythia-1.4b.json` 裡 `L1-gardening-1` 這一題的原始提示詞是 `"What do bees carry from flower to flower that allows plants to produce seeds?"`（蜜蜂替植物傳什麼、讓植物可以結種子？），模型的實際輸出（`greedy_continuation` 欄位）是：

> `"\n\nA:\n\nBees are not the only pollinators. There are many other insects that are pollinators.\n\nA"`

模型沒有直接回答「花粉」，而是先換行、自己生出一個 `"A:"` 標籤，然後寫出一段像是問答網站貼文的內容——這正是「把問題當成一段文章的開頭去接續」的實例。這個問題被抓到後，同一題在正式版題庫 `battery/battery.json` 裡（id 同樣是 `L1-gardening-1`）改成了 cloze 格式：`"Bees move from flower to flower carrying a fine powder called"`，讓正確答案 `"pollen"`（花粉）剛好是模型該接的下一個詞，不再需要模型「理解這是個問題」。另外 `harness/run_pilot.py` 的 `manipulation_check()` 函式（第 150–162 行）裡，`l1_expected_in_output` 這個欄位就是拿來檢查「即使格式改了，模型的輸出裡到底有沒有真的出現預期答案」的操縱檢查（manipulation check，見卡 17）。

**常見誤解**：
1. 「這兩個模型比較笨，才會答不出問題」——不是能力問題，是訓練目標問題。Base 模型的訓練目標從頭到尾只有「預測下一個詞」，從沒被教過「使用者的問句之後應該接一個直接的答案」這種對話禮儀，這是行為模式的缺失，不是知識或推理能力的缺失。
2. 「換成 cloze 格式後，這題測的東西跟原本的問答題一樣」——嚴格來說不完全一樣，cloze 格式更乾淨地量到「下一個詞預測」本身，但也代表我們刻意放棄了「模型有沒有『理解』這是個問題」這件事本身的測量——這是本研究為了讓量測乾淨而接受的一個取捨，不是沒有代價。

**答辯模擬題**：
- Q：那你們乾脆用聽得懂指令的模型不就沒這個麻煩了嗎？
  A：聽指令的模型（instruct 模型）幾乎都不公開完整訓練語料，我們就沒辦法用 infini-gram 查它到底背過什麼——而「有沒有背過」正是本研究區分回憶跟創造最重要的 ground truth（真相基準）。所以我們選擇忍受 base 模型「不聽話」的麻煩，換取「知道它真的背過什麼」的確定性。
- Q：你們怎麼知道 cloze 格式真的解決了這個問題，不是猜的？
  A：`run_pilot.py` 裡有專門的操縱檢查（`manipulation_check` 函式），會記錄每一題的實際輸出裡有沒有真的出現預期答案的字樣，這是拿真實生成的文字去核對，不是憑感覺判斷格式有沒有生效。
