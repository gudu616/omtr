# 23. 置換檢定與尺的校準（Permutation Tests & Calibration）

**一句話白話版**：置換檢定是「把標籤洗牌幾萬次，看真實資料有多突出」的比大小遊戲；但這把尺自己也可能是歪的——所以在拿它量真資料**之前**，先餵它幾百份「答案已知是沒差」的假資料，數它誤報「有差」的比率是不是說好的 5%。這個步驟叫校準（calibration）。

**為什麼本研究用得到**：L0P 交叉對照的主分析（A1）要在「配平可預測度」之後比較記憶組與對照組，這件事用的是 ANCOVA 加標籤置換。我們在解盲前用合成資料校準這把尺，發現一個教科書等級的陷阱：**兩組的 gold 量程一個寬一個窄時，直接置換標籤會反保守**——名目上 5% 的誤報率，實測膨脹到 8–11%。尺往「有發現」那邊歪，正是這個專案最忌諱的方向。修法是比較前先把每個係數除以它自己的標準誤（studentization，學生化），修完誤報率回到 5% 上下，抓真效應的能力沒有損失。這一切都發生在看到真資料之前，所以修尺的理由不可能來自「想要某個結果」。

**再深一點**：置換檢定的邏輯是「如果條件標籤跟結果無關，那把標籤隨便洗牌，統計量的分布應該跟真實的差不多」。陷阱在於：洗牌會把標籤**均勻地**撒到整個 gold 量程上，但真實的標籤分布是結構性的（記憶組佔的量程比對照組寬）。洗牌後的世界比真實世界「更平衡」，算出來的虛無分布就太窄，真實資料稍微偏一點就顯得「突出」——這就是反保守。學生化為什麼有救：除以標準誤之後,統計量的尺度會把「這個樣本配置本來就比較晃」的資訊帶進來,置換分布跟真實抽樣分布就對得更齊。另一個要點:**四個 Pythia 模型共用同一批題目,所以它們的統計量會同進同退**——置換時必須四個模型共用同一次洗牌(OLMo 獨立洗),否則就是把同一個巧合數了四次。這跟卡 16 講的「不要把五次跑當五次獨立複製」是同一件事在檢定層的版本。

**在我們的程式碼／數據裡**：`harness/l0p_analysis.py` 的 `fit_ancova`（β 與 t 都算）與 `a1_primary`（共用洗牌的置換迴圈,20,000 次,seed 20260822）。校準腳本在 session 暫存區（`diagnose_a1_schemes.py`：三種方案 × 四種虛無情境 × 150 份假資料）,量到的數字記錄在 `l0p_analysis.py` 檔頭 docstring:裸 β 版誤報率 0.080–0.115,學生化後 0.047–0.063,連「重疊區內某條件只剩 0–4 題」的嚴苛情境都維持 0.053–0.063。正式跑出來的 A1 合併 p = 0.0986——落在解盲前就宣告的脆弱區（0.02–0.10）,所以 v0.7 照凍結規則標註「對檢定校準脆弱」;殘留誤差的方向是把 p 往小報,所以「不顯著」這個讀法是穩的那邊。

**常見誤解**：
1. 「置換檢定是無母數的,所以不會錯」——置換檢定不假設分布,但它假設**虛無之下標籤可交換**。標籤跟共變數（這裡是 gold）有結構性關聯時,這個假設就破了,誤報率照樣膨脹。無母數 ≠ 免檢驗。
2. 「校準用的假資料是編的,量出來的膨脹率不算數」——量值確實依賴假資料的參數（所以我們只引用方向與量級,並在文件裡註明生成參數未經真資料校準）;但「膨脹存在、方向朝反保守」在四種不同的合成結構下全部重現,而且有代數上的理由。方向穩、大小不穩,引用時就只引方向。

**答辯模擬題**：
- Q：你們解盲前改了檢定方法（從裸 β 換成學生化 t），這不就是調參數調到喜歡為止嗎？
  A：三個防線。第一,改動發生在任何人看到任何真實數字之前,時間順序記錄在流程日誌第二十三步。第二,改動的依據是可重跑的校準實驗:固定種子的假資料、已知答案是「沒差」,裸 β 版誤報 8–11%、學生化版 5% 上下——選後者不是偏好,是量出來的。第三,預註冊凍結的要素（估計量、置換單位、共用洗牌結構、次數、種子、雙尾）一個都沒動,學生化只改「置換分布跟觀察值比的那個統計量」,這是置換檢定文獻裡的標準作法。
- Q：p = 0.0986 離 0.05 這麼近,多跑幾個模型不就顯著了?
  A：不能這樣做,兩個理由。第一,預註冊寫死了五個模型與判定規則,跑到顯著為止（optional stopping）正是預註冊要防的行為。第二,就算真的顯著了,方向也是**正**的——記憶組在配平之後反而略不篤定——那不是記憶假說要的方向,加樣本只會把「反方向」量得更準。
